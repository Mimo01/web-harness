Web LLM Harness Connector

1. Harness page

Only pages served from these origins may use the extension. Enter the address you open the harness at (e.g. https://intranet.example.com).

Pages opened from a file all share one origin, file:// — the browser has nothing finer to offer, so listing it would otherwise mean every HTML file on this computer. To stop that, the extension binds the grant to a single folder: the first local page that identifies itself as the harness. Anything outside that folder is refused. Add file:// only if you must, enable "Allow access to file URLs" in the extension details, and prefer hosting the harness at an http(s) address where a real origin can be checked.

    2. APIs it may call

    The harness may call REST APIs on these origins through the extension, using your browser login (cookies) or a token the harness sends. Adding one asks Chrome for access to that site; removing it gives the access back. The extension starts with access to nothing.

      Origins are scheme + host (+ port).
